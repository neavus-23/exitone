EXITONE

observe · correlate · suggest — the human decides and executes

A terminal-native investigation engine for pentesting, labs, and CTF-style security research. Structured facts are parsed and correlated in Go first; a local LLM only narrates, explains, and fills genuine gaps — it never invents a finding and never runs a command on its own.

Why ExitOne

Deterministic before generative

Every fact, score, and stage comes from a real row in SQLite. The LLM narrates what Go already computed — it never gets to invent a finding, a credential, or a next step.

Persistent investigation state

Evidence, observations, entities, relationships, objectives, candidates, actions, outcomes, and hypotheses all live in one queryable model, not scattered across shell scrollback.

Explainable, human-executed

Every suggested command carries its score terms and can be inspected with why. ExitOne stages the action — pressing Enter is always the operator's decision.

Cross-tool correlation

Methodology triggers key off entity types and relationships, not hard-coded tool names, so evidence from any scanner feeds the same investigation graph.

LLM-narrated reporting

exitone report assembles scope, findings, credentials, and timeline from real data, with prose written by the local LLM in small, bounded, per-section calls.

Runs entirely local

ExitOne manages its own local LLM sidecar (or an OpenAI-compatible endpoint you point it at) — no hosted AI provider is required.

Install

git clone https://github.com/neavus-23/exitone.git
cd exitone

go build -o exitone ./cmd/exitone
mkdir -p "$HOME/.local/bin"
install -m 0755 exitone "$HOME/.local/bin/exitone"

exitone start

Requires Go 1.27+. Full requirements, the Control Console command map, and the TUI's Overview/Graph/Vault/Chat views are documented in the project README.

ExitOne is intentionally human-in-the-loop. Use it only in environments you own or are explicitly authorized to test.
